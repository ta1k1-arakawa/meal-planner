# 増量 v2（bulking-v2）— 朝食なし・筋肉中心の増量プロファイル

2026-11-10、利用者の要望に合わせて夕食専用プランナーを1日全体の増量管理へ拡張した。
既存の認証、在庫台帳、買い物リスト生成、写真購入はそのまま維持している。
移行は追加のみの `0008_bulking.sql` で行い、`0001`〜`0007` は変更していない。

## 前提（利用者プロファイル）

- 身長183cm・体重60kg、筋トレ週3回程度。筋肉中心に増量し、脂肪が少しつくのは許容。
- 目標：約3,000 kcal/日、たんぱく質115〜125 g/日。体重は週+0.2〜0.4 kg（7日平均で判定）。
- **朝食は食べない**（固形物がほぼ無理）。朝は飲める日だけ任意の飲み物枠。
- 苦手食材：オートミール、ピーナッツバター。初期設定で生成から除外する。
- 食費：月25,000円が目標。買い物は火曜・土曜サイクル（従来機能を維持）。
- 米は5kg約3,000円で買う。高い時はパスタへ置換する。

## 1日の使い方

| 枠 | 時刻の目安 | 目標 |
| --- | --- | --- |
| 朝の飲み物（任意） | 起床後 | 200 kcal / P 7 g（ココア牛乳。飲める日だけ） |
| 昼食 | 12:30ごろ | 1,150 kcal / P 50 g |
| 間食 | 15:30〜16:30 | 450 kcal / P 18 g |
| 夕食 | 19:30〜20:30 | 1,100 kcal / P 50 g |
| 夜食 | 22:30ごろ | 325 kcal / P 13 g |

合計は朝の飲み物を除いて約2,950〜3,000 kcal / P 約120 g。

日常の操作は次の通り。

1. 買い物日（火・土）に「今日買う食材を表示」で夕食と買い物リストを作り、
   今日画面の「昼・間食・夜食を作る」で残りの枠も生成する。
   買い物リストの不足量は夕食だけでなく昼・間食・夜食・朝の飲み物枠も含めて計算される。
2. 買い物確定時に、各食材の**合計価格（円・任意）**を入力する。月次集計と単価警告に使う。
   鶏肉100g 110円、卵1個30円、牛乳1L 240円、米5kg 3,200円、パスタ1kg 250円が上限の目安で、
   入力単価が超えると買い物画面に警告が出る。
3. 食べたら各枠の「レシピ通りに食べて完了」を押す。在庫が消費され、その日の確認済み栄養に計上される。
   食べなかったらスキップ（在庫は減らない）。
4. 毎朝、体重を今日画面に入力する。7日平均と前週比、調整提案が表示される。
5. 今日画面の「今月の食費」で、予算25,000円に対する今月の支出と、今日の献立の食材費の目安を見る。

## 調整ルール（体重）

`GET /api/body-weight-logs` が7日平均（各週ウィンドウに3件以上の記録が必要）を返す。

- 週の増加が **+0.2 kg未満で2週続いたら**：夜食に **+200 kcal** の提案。
- 週の増加が **+0.5 kgを超えたら**：間食から **−200 kcal** の提案。
- +0.2〜0.5 kgの範囲：維持。1週だけ少ない場合は様子見（watch）。

提案は表示のみで、食事量は自動では変わらない。利用者が設定画面で枠目標を書き換える。

## 実装の要点

- `meal_slot_plans`（新規テーブル）：昼食・間食・夜食・朝の飲み物の予定。
  夕食は従来通り `meal_plans` が正本で、二重管理しない。
  `POST /api/day-plans/generate` が買い物サイクル分を生成し、在庫の仮想予約と
  買い物不足量の再計算（`reconcileShopping`）には夕食と合算して反映される。
- レシピに `slot` を追加。夕食生成の候補は `slot = dinner` のみ。
  増量レシピ17件（昼5・夕5・間食3・夜食3・朝の飲み物1）を追加し、カタログは全47件。
  分量は利用者の増量プラン文書（ご飯400g級、パスタ乾麺180gなど）に基づく。
- 苦手食材は既存の `excludedIngredients`（設定）で管理し、生成の適格判定 `eligible()` が
  全枠共通で適用する。`0008` で `oatmeal` と `peanut_butter` を初期除外に加えた。
  設定画面からいつでも変更できる。
- 価格は専用テーブル `purchase_prices` に記録する（買い物テーブルへの列追加はしない。
  旧形式の確定リクエストは価格なしで従来通り動作する）。
  `GET /api/costs/summary?month=YYYY-MM` が月の支出・予算残・日別支出と、
  最新の購入単価から見積もった「今日の食材費」を返す。単価上限は `worker/price-caps.ts`。
- 設定に `monthlyBudgetYen` と `slotTargets`（枠ごとの kcal/たんぱく質）を追加。
  `GET /api/settings` は移行前のDBでも読めるよう、新列が無い場合は既定値で補う。
- 就寝前シェイクのプリセットは残してあるが、夜食の枠計画がある日は
  日別集計の予定に二重計上しない。

## 既存テストへの変更

- 統合テストの移行リストに `0008_bulking.sql` を追加（アップグレード検証テストでは従来通り段階適用）。
- カタログ件数の検証は30件→47件に更新し、75℃加熱の検証は生の肉・魚・卵を含むレシピに限定した。
- 日・水サイクルと夕食950 kcalを前提にしていた Issue #4 の3テストは、
  冒頭で旧設定を明示的に保存してから従来のシナリオを検証するよう変更した。
  「日・水リストの無効化」テストの米合計1400g固定の検証は、米を使わない夕食（サバ缶パスタ）が
  増えたため、「買い物リストが献立の累計需要と一致する」という性質の検証に置き換えた。

## 未実装・後続範囲

- 枠レシピの候補比較・差し替えUI（夕食には既存の候補機能がある）。枠は生成とスキップで運用する。
- レシート写真からの価格自動読み取り（写真購入は在庫登録のみ。価格は手入力）。
- 体重に応じた枠目標の自動変更（提案の表示まで）。
- 本番への移行・デプロイは従来通り手動。`0008` は本番未適用。
